OBJECTIF

L'Administrateur est responsable du bon fonctionnement de la plateforme.

Il configure le système.

Il garantit la sécurité.

Il gère les utilisateurs.

Il gère les rôles.

Il gère les paramètres.

Il ne prend pas les décisions métier concernant le traitement des tickets.

L'Administrateur est le responsable technique et fonctionnel de la plateforme.

==========================================================
ACTIONS INTERDITES
==========================================================

L'Administrateur ne doit jamais :

Modifier le contenu métier d'un ticket sans justification.

Supprimer un historique.

Supprimer un journal d'audit.

Prendre des décisions métier à la place de la Direction DSI.

Modifier une décision stratégique.

==========================================================
PERMISSIONS CONFIGURABLES
==========================================================

Certaines fonctions peuvent être limitées.

Exemples :

Peut gérer les utilisateurs.

Peut gérer les rôles.

Peut gérer les workflows.

Peut gérer les sauvegardes.

Peut gérer les paramètres.

Toutes les permissions sont configurables.

==========================================================
EXEMPLE
==========================================================

Un nouveau Chef de Service arrive.

L'Administrateur :

• crée son compte

• lui attribue le rôle correspondant

• l'associe au bon service

• vérifie ses permissions

Le nouvel utilisateur peut immédiatement accéder à son espace.

==========================================================
REGLE ABSOLUE
==========================================================

L'Administrateur administre la plateforme.

Il ne pilote pas le métier.

Toutes les opérations techniques doivent être :

• sécurisées

• journalisées

• auditables

Toute modification de configuration doit laisser une trace.
