==========================================================
ADMINISTRATEUR
PARTIE 3
INTERFACES ET EXPERIENCE UTILISATEUR
==========================================================

OBJECTIF

Cette partie décrit l'ensemble des interfaces accessibles à
l'Administrateur.

Chaque interface doit respecter la charte graphique officielle de
l'application (design moderne, glassmorphism maîtrisé, responsive,
accessible et cohérent).

Toutes les actions disponibles dans l'interface doivent être validées par
les permissions définies côté backend.

==========================================================

==========================================================
MODALES STANDARD
==========================================================

Toutes les opérations critiques utilisent une modale.

Exemples :

• Confirmation de suppression logique
• Confirmation de désactivation
• Réinitialisation du mot de passe
• Restauration d'une sauvegarde
• Attribution d'un rôle
• Modification d'un SLA

Chaque modale affiche :

• le contexte
• les impacts
• les boutons Confirmer / Annuler

==========================================================
ETATS VIDES
==========================================================

Chaque écran possède un état vide avec :

• illustration
• message explicatif
• action recommandée

Exemple :

"Aucun utilisateur trouvé."

Bouton :

Créer un utilisateur

==========================================================
MESSAGES D'ERREUR
==========================================================

Les erreurs doivent être explicites.

Exemples :

"Impossible de supprimer ce rôle car il est utilisé."

"Ce département contient encore des services."

"La sauvegarde a échoué."

==========================================================
REGLES UX
==========================================================

Toutes les listes proposent :

• recherche instantanée

• filtres combinables

• tri multi-colonnes

• pagination

• vue grille / liste lorsque pertinent

• export

• responsive desktop / tablette

Les actions critiques doivent toujours demander une confirmation.

Les formulaires doivent afficher les erreurs champ par champ.

==========================================================
REGLE ABSOLUE
==========================================================

L'interface Administrateur constitue le centre de configuration de la
plateforme.

Elle doit être :

• simple

• cohérente

• sécurisée

• rapide

• entièrement pilotée par les permissions du backend.

Aucune action d'administration ne doit être visible ou exécutable sans
l'autorisation correspondante.
